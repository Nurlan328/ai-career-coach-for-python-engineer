# GIL (Global Interpreter Lock)

GIL — это мьютекс в CPython, который позволяет выполнять байткод Python только
одному потоку в каждый момент времени. Из-за него многопоточность не даёт
ускорения для CPU-bound задач: потоки не выполняются по-настоящему параллельно.

Для I/O-bound задач (сеть, диск, БД) потоки полезны: пока один поток ждёт I/O,
GIL освобождается и другой поток работает. Поэтому `threading` хорош для I/O,
но не для вычислений.

Чтобы задействовать несколько ядер для CPU-bound работы, используют
`multiprocessing` (отдельные процессы, у каждого свой интерпретатор и GIL) или
выносят тяжёлые вычисления в C-расширения / numpy, которые освобождают GIL.

В Python 3.13 появился экспериментальный free-threaded режим (PEP 703) без GIL,
но это пока опционально. Практический вывод: для масштабирования CPU-bound
нагрузки — процессы или нативный код; для конкурентного I/O — asyncio или потоки.
