# SQLAlchemy: проблема N+1 и загрузка связей

Проблема N+1 возникает, когда вы загружаете список объектов (1 запрос), а затем
обращаетесь к связанной коллекции каждого — и ORM делает по запросу на объект
(ещё N запросов). На больших списках это убивает производительность.

Lazy loading (по умолчанию) подгружает связь при первом обращении — удобно, но
именно он порождает N+1. Eager loading загружает связи заранее:

- `selectinload(Model.rel)` — отдельный запрос `IN (...)` для всех связей; лучший
  выбор для коллекций (one-to-many).
- `joinedload(Model.rel)` — один запрос с JOIN; хорош для many-to-one / one-to-one.

Пример: `select(User).options(selectinload(User.posts))` загрузит посты всех
пользователей одним дополнительным запросом вместо N.

Также важны `session`, identity map (один объект на PK в сессии) и unit of work
(изменения накапливаются и сбрасываются на flush/commit). При async-движке связи
нужно грузить eager-стратегиями, потому что ленивая подгрузка в async требует
особой настройки и часто приводит к ошибкам.
