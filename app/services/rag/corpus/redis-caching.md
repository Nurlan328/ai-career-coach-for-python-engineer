# Redis и кэширование

Redis — это in-memory хранилище структур данных: строки, hash, list, set, sorted
set, stream. Часто используется как кэш, брокер сообщений и хранилище сессий.

Cache-aside (lazy loading) — самый частый паттерн: приложение сначала смотрит в
кэш; при промахе читает из БД и кладёт значение в кэш с TTL. Write-through
обновляет кэш синхронно при записи в БД; write-behind — асинхронно.

TTL (`EX`/`PX`) ограничивает время жизни ключа — основной способ инвалидации.
Явная инвалидация по ключу нужна, когда данные меняются раньше TTL. Опасность —
cache stampede: при одновременном промахе многие запросы бьют в БД; помогают
блокировки, ранний пересчёт и jitter в TTL.

Для распределённой блокировки используют `SET key val NX PX ttl` (по возможности
паттерн Redlock). Redis однопоточный по обработке команд, поэтому операции
атомарны; сложные атомарные сценарии пишут на Lua через `EVAL`.
